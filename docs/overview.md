# Обзор Проекта

`athletics-telegram-bot` автоматизирует редакционный процесс Telegram-канала `@beyond_the_1ine`.

Проект не должен заменять редактора. Его задача: собрать релевантные новости, подготовить аккуратные черновики и дать человеку быстро принять решение.

## Что Делает Бот

- собирает новости из RSS-источников по бегу и лёгкой атлетике;
- ранжирует новости по важности;
- отсеивает дубликаты по URL и content hash;
- пишет русскоязычные черновики через OpenAI API;
- отправляет черновики в draft-канал с кнопками;
- публикует в основной канал только после подтверждения;
- хранит историю источников, черновиков и опубликованных постов в Postgres.

## Что Бот Не Делает

- не публикует автоматически, если `AUTO_PUBLISH=false`;
- не проверяет факты за пределами текста RSS item;
- не скачивает и не перезаливает изображения без отдельной логики прав;
- не делает routine-вечернюю сводку;
- не заменяет редакционное решение человека.

## Компоненты

### FastAPI Web Service

Файл: `app/web/main.py`.

Сервис принимает:

- health check: `GET /health`;
- Telegram webhook: `POST /api/telegram/webhook`;
- admin-команды: `POST /admin/...`.

### Scheduled Jobs

Файлы:

- `app/jobs/digest.py`;
- `app/jobs/hourly.py`.

На Railway это отдельные сервисы с cron-расписанием:

- `morning-digest`: утренняя тематическая сводка;
- `hourly-monitor`: выборочный мониторинг важных новостей в течение дня.

### Pipeline

Файл: `app/pipeline.py`.

Pipeline делает основную работу:

1. Загружает источники и watch terms.
2. Собирает RSS items.
3. Ранжирует все items.
4. Сохраняет source items в Postgres.
5. Пропускает URL, для которых уже есть черновик.
6. Генерирует новые черновики до лимита.
7. Отправляет черновики или публикует сразу, в зависимости от `AUTO_PUBLISH`.

Важная деталь: лимит применяется после пропуска дубликатов. Если первые новости уже использовались, бот должен добрать следующие.

### OpenAI Writer

Файл: `app/writer/openai_writer.py`.

Writer берёт:

- editorial rules из `config/editorial.md`;
- title, summary и URL source item;
- режим запуска: `morning` или `hourly`.

Он просит модель вернуть только текст поста, без markdown и без выдуманных фактов.

Модель выбирается по режиму: hourly использует более экономичный `OPENAI_HOURLY_MODEL`, а morning/analysis используют `OPENAI_STRONG_MODEL`.

### Telegram Approval Flow

Файлы:

- `app/telegram/client.py`;
- `app/telegram/webhook.py`;
- `app/telegram/formatting.py`.

Черновик отправляется в draft-канал с inline keyboard:

- `Опубликовать`;
- `Отклонить`;
- `Переписать`.

Нажатие кнопки приходит в webhook. Webhook проверяет secret, находит draft в базе и выполняет действие.

## База Данных

Миграция: `migrations/001_init.sql`.

Таблицы:

- `source_items`: новости из источников;
- `drafts`: черновики и их статусы;
- `published_posts`: опубликованные посты;
- `run_logs`: заготовка под журнал запусков.

## Статусы Черновиков

Основные значения:

- `pending`: черновик создан и ждёт решения;
- `published`: опубликован в основной канал;
- `rejected`: отклонён;
- `rewrite_requested`: помечен на переписывание.

Сейчас `rewrite_requested` только меняет статус. Автоматическое переписывание отдельным циклом пока не реализовано.
