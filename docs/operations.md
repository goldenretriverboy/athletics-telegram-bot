# Операции

Этот документ про ежедневную работу с ботом.

## Обычный День

### 09:00 Asia/Almaty

`morning-digest` создаёт утреннюю тематическую сводку.

Ожидаемое поведение:

- 0 постов, если сильных тем нет;
- 1 большой сводный черновик или несколько черновиков только при сильных отдельных темах;
- черновики приходят в draft-канал;
- редактор нажимает `Опубликовать`, если текст подходит.

### 10:00-22:00 Asia/Almaty

`hourly-monitor` проверяет новости раз в час.

Ожидаемое поведение:

- чаще всего `created=0`;
- если есть важная тема, создаёт 1 черновик;
- максимум обычно 2 черновика за запуск;
- слабые новости пропускаются.

Если несколько hourly-проверок подряд не создали черновики, бот отправляет служебный статус в draft-чат. Это не пост для публикации, а сигнал, что cron работает и сильных новых тем нет.

## Ручной Запуск Через Admin Endpoint

Admin endpoints защищены заголовком:

```text
X-Admin-Secret: <TELEGRAM_WEBHOOK_SECRET>
```

### Hourly

```bash
curl -sS -X POST \
  -H "X-Admin-Secret: $TELEGRAM_WEBHOOK_SECRET" \
  "$PUBLIC_BASE_URL/admin/run/hourly"
```

### Morning Digest

```bash
curl -sS -X POST \
  -H "X-Admin-Secret: $TELEGRAM_WEBHOOK_SECRET" \
  "$PUBLIC_BASE_URL/admin/run/digest/morning"
```

### Test Draft

```bash
curl -sS -X POST \
  -H "X-Admin-Secret: $TELEGRAM_WEBHOOK_SECRET" \
  "$PUBLIC_BASE_URL/admin/test-draft"
```

Создаёт тестовый черновик в draft-канале.

## Проверка После Деплоя

1. Проверить Railway deployment status.
2. Проверить `/health`.
3. Проверить, что cron-сервисы тоже redeploy-нулись.
4. При изменении pipeline сделать ручной `/admin/run/hourly` или `/admin/run/digest/morning`.
5. Проверить draft-канал.

## Если Нужно Опубликовать Пост

1. Дождаться черновика в draft-канале.
2. Прочитать текст.
3. Проверить источник.
4. Проверить, что нет странных формулировок.
5. Нажать `Опубликовать`.
6. Проверить основной канал.

## Если Нужно Переписать Пост

Сейчас кнопка `Переписать` только меняет статус на `rewrite_requested`.

Практический процесс пока такой:

1. Нажать `Отклонить` или `Переписать`.
2. Сформулировать, что не так.
3. Запустить ручной пост через отдельную редакционную работу или добавить будущий endpoint rewrite.
